# AGENTS.md

## Project knowledge (maintained by /crew)

### Architecture

- **Non-production workshop for Arbitrum PGA + Fast Feed.** Every command except `npm run sim` (local-only) and `npm run key:new` (no network) takes `--local` (Anvil + mock sequencer + mock Fast Feed, chainId 31337) or `--testnet` (Arbitrum Sepolia, 421614); `shared/config.ts` is the only place they differ and the single source of local parameters. Consequence: feature code must not branch on network, except `--local`-only sequencer narration, TEST minting, the round/block-tick sync (`sim_msUntilNextRound`, `sim_msUntilNextBlock`), stack self-start and local wallet funding, the local `pga_round` lookup via `sim_boostTrace` (`pgaRoundOf` in `pga/bot/common.ts`), and the local-only flood scenario and traffic generator.
- **Feature-first layout (D1):** `shared/` (config.ts, the single source of parameters, and narrate.ts), `sim/` (the local stack), `fast-feed/` (`client/`, `mock/` = the local feed and its ticket auth), `pga/` (`rules/pga-core.ts`, `bot/`, `scripts/demo.sh`), `combo/` (race, demo and `pga:slot`); each has its `test/` and `README.md`, plus `docs/setup.md`. Contracts stay one Foundry tree under `contracts/src/{fast-feed,combo}` and `contracts/test/combo`. Dependency rule, enforced by `shared/test/layout.test.ts`: `fast-feed/` and `pga/` never import each other; among the features only `combo/` imports both (`sim/`, the stack, also does); nothing outside `combo/` imports it; `shared/` imports no feature (only `shared/test/config.test.ts` may import `sim/banner`); `sim/` imports only `pga/rules`, `fast-feed/mock`, `fast-feed/client/abi.ts` and `shared/`. Consequence: a test that needs both features lives in `combo/test` (e.g. `pga-order.integration`).
- **Stack:** TypeScript + viem + ws on Node >= 22, run with `tsx`; tests use `node:test` (`npm test`, glob `*/test/**/*.test.ts`), types via `npm run typecheck`; Solidity via Foundry (`foundry.toml`, `contracts/src`, solc 0.8.34). Foundry binaries are resolved from PATH, then `~/.foundry/bin`.
- **Local stack (`sim/`):** Anvil runs `--no-mining --order fifo` behind our JSON-RPC proxy (`sim/rpc.ts`, :8547), so our sequencer (`sim/sequencer.ts` + pure `pga/rules/pga-core.ts`) is the only ordering. The mock feed (`fast-feed/mock/feed.ts`, :9642) publishes each round's txs right after execution. `sim/index.ts` `startOrAttach()` starts the stack in-process or attaches to a running one; the starting process owns Anvil and kills it on exit.
- **PGA ordering (`pga/rules/pga-core.ts`, pure):** `effectiveTip = min(maxPriorityFee, maxFee − baseFee)`, clamped at 0. A legacy tx's gasPrice counts as both values (assumption). `selectRound(queue, baseFee, nextNonce, mode, opts {boostOf, maxTxs}) -> {ordered, held, deferred, priorities}` drains a priority queue seeded with each sender's next nonce (from Anvil at round time): highest effective tip first, then arrival. Once a sender's N is included, its N+1 joins at its own tip, so N+1 is never placed before N. With `MAX_TXS_PER_ROUND` set (a tx-count stand-in for Arbitrum's 32 Mgas / 95 kB block-full rule, shown in the banner and `sim_info`), a round includes at most that many txs and the rest are `deferred` to the next round. `runRound` then computes p = the queue priority (tip + boost) of the last included tx, or 0 if none, and adds p/(2K), floored in wei, to every tx still waiting, including gap-held ones (an assumption). The boost changes only the queue key, never the fee; the local-only `sim_boostTrace(hash)` exposes it. Deferred txs never count toward the gap hold. Without a cap nothing is deferred. Simulator assumptions are documented once, in `sim/README.md`. Txs behind a nonce gap are `held`, never sent to Anvil, and dropped with a log after `GAP_HOLD_ROUNDS` (default 10, an assumption). `fifo` mode ranks every tx at tip 0 but keeps the nonce rule. `pendingNonce` walks contiguously from Anvil's nonce, so held txs do not bump it. The sequencer submits the drained batch to Anvil one tx at a time, awaiting each, so `--order fifo` keeps our order and receipts and feed `tx_index` match it. `--fifo` / `SIM_ORDER=fifo` switches to arrival order (shown in the banner and in `sim_info.ordering`) for comparisons. Each round's queue and drained order are narrated through `internal()`. A tx that Anvil accepts but leaves out of the mined block (e.g. unaffordable) is logged as dropped and evicted with `anvil_dropTransaction`, so it cannot be mined later outside our ordering. A batch whose every tx Anvil rejects at submit mines no block; if Anvil accepts them but omits all of them (e.g. Anvil rejects nonce N at submit but accepts N+1 as a future tx), an empty block is still mined and narrated as such at a block's last round (since B6 an empty provisional block for a non-last round is reverted).
- **Local funding (`sim/fund.ts`):** at stack start the addresses of `PRIVATE_KEY` and `MY_ADDRESSES` get 1000 ETH via `anvil_setBalance`, printing only the address, so `--local` commands work even with a testnet key in `.env`.
- **Anvil dev accounts:** Anvil runs with 20 dev accounts from the public default mnemonic. `ANVIL_ACCOUNT_MAP` in `shared/config.ts` is the single map: 0–2 user/demo wallets (in the flood, account 0 is the zero-tip sender and account 1 the later arrival; in the race, 0 is "mine" and 2 the rival), 3–8 flooders, 9 Tickets admin and Race operator, 10–19 `sim/traffic.ts`; `slotSenders` 0–3 for `pga:slot`; `demoCompetitors` 3–5 for the demo's round-2 competitors (account 3 is shared with the flooders; the two never run together). All indexes have a role on the shared stack (tests on their own stacks may reuse them), so update the map before giving any account a new role.
- **K = 2 PGA rounds per local block (B6), as on Arbitrum One:** slow preset 2000 ms (two 1000 ms rounds), fast 250 ms (two 125 ms), `--slowmo` 25000 ms (two 12.5 s rounds, ×100). Each block works like this:
  - Round i has `pga_round = ((i−1) mod K)+1` and block slot ceil(i/K) (`sim/blocks.ts`).
  - Each non-last round is mined as a provisional block N after an `evm_snapshot`.
  - Each later round does `evm_revert`, then `anvil_dropAllTransactions` (the revert puts the txs back in Anvil's pool), then resubmits the published txs plus the new ones in order. It re-mines N with the same explicit timestamp T and the pinned base fee.
  - Anvil 1.8.6 keeps receipts, timestamp and prevrandao identical. Equal timestamps are allowed and T−1 is rejected, so T = max(now, parent timestamp). Always pass T: a plain `evm_mine` after a revert can reuse the old head's time.
  - A read gate (`RwGate`) holds the proxy's and ticket auth's Anvil calls from revert to the end of the mine. Between rounds, `latest` sees round 1's effects.
  - A runtime check compares every published receipt with the final one. A mismatch logs `FEED RECEIPT MISMATCH` and counts in `receiptMismatches` (`sim_info`, `sim_blockInfo`). There is no re-publish.
  - The block is revealed at the final mine + `BLOCK_PUBLISH_DELAY_MS`.
  - `MAX_TXS_PER_ROUND` stays per round, so a block holds at most K×cap txs. All rounds share T (assumptions in `sim/README.md`).
  - New local RPC: `sim_msUntilNextBlock`, `sim_blockInfo`, and `sim_arrivals(block, round)` (C8: per-tx `arrivedAtMs` for the last 32 blocks, the only source of arrival times; Arbitrum does not publish them). `sim_boostTrace` included entries carry `block` and `pgaRound`.
- **Blocks, rounds and visibility:** a block with no ordered txs in any round is not mined. A feed message's `timestamp_ms` is the time its round was ordered, taken before Anvil executes it. The proxy hides block N (block number, blocks, receipts, txs, logs) until its last round's final mine + `BLOCK_PUBLISH_DELAY_MS`, so round-1 txs lead RPC visibility by about one round more than round-2 txs. State reads at `latest` (`eth_call`, balances, estimates) are not gated and see earlier rounds of the open block. **"Same round" means `(block_number, pga_round)`; `tx_index` is block-wide, so round-level claims use the position within the round.** Locally `pga_round` comes from the feed or from `sim_boostTrace`; on testnet bots, the probe and `demo.sh` judge by block only and say so. Local bots, `demo.sh`, the probe and `pga:slot` sync to `sim_msUntilNextBlock` so their batch lands in round 1. The race sends `open` just after a block starts, so the feed claim lands in round 2 of that block and a poller in a later block.
- **Block time override (B5):** `--block-ms` / `SIM_BLOCK_MS` (precedence flag > env > preset) replaces B of the chosen preset; K stays 2, so a round is B/2. It must be an even whole number from 250 to 600000 (`MIN_BLOCK_MS`/`MAX_BLOCK_MS`; `--slowmo` with `--block-ms` is an error), parsed in `shared/config.ts`; `sim/cli.ts` exits 2 on any `ConfigError`. The banner adds an override line next to Arbitrum One's 250/125 ms, and attaching commands read `blockMs`/`roundMs` from `sim_info`. `sim/cli.ts` warns when the requested block time differs from a running stack.
- **Local ticket round (C5):** `ticketRoundSeconds(blockMs, env)` in `shared/config.ts` gives `max(30 s, 4 × B)` (30 s on slow and fast, 100 s with `--slowmo`), so a purchase visible only after its block closes still lands in the intended round. An explicit `TICKET_ROUND_SECONDS` wins, and a `WARNING:` line warns when it is below 4 × B. `localParams.tickets` carries `roundAdapted`/`roundWarning`. The long `npm run sim` banner and the demo's chapter-1 compact notes print the adaptation `NOTE:`; demo chapter 3 prints one ticket-round NOTE against Arbitrum One's 24 h (E1). Ticket decisions scale with B and equal the old constants at B = 2000. They are in `combo/race.ts` (`purchaseLandMs`, `renewMinToBuyMs` = 1.5·B, `renewThresholdMs` = max(15 s, 4·B), `renewDecision(…, blockMs)`), `combo/scenarios.ts` (`minTicketRemainingMs`, `defaultTrialMs`) and `combo/demo.ts` (`chapterNeedMs`). `renewTickets` returns undefined (the caller rebuys) when `renewTooLate(activeUntil, now, B)` says too little of the ticket's own lifetime is left. The `tickets:buy` CLI has its own B-aware guard in fast-feed (`purchaseRoomDecision`/`ensureRoundRoom`): it waits for the next round with a `NOTE:` when the purchase would not land in time. Traffic counts a tx as dropped only after `dropAfterMsFor(B)` = max(20 s, 2·B).
- **Output palette (C6):** `shared/narrate.ts` is the single palette and printer. Printers:
  - `step`: cyan `==>`.
  - `note`/`noteLines`: yellow, exactly one `NOTE:` prefix; wrapped continuation lines are indented 6 spaces.
  - `warn`: bold yellow `WARNING:` on stdout, for flags ignored on attach and a `TICKET_ROUND_SECONDS` below 4×B.
  - `important`: bold+inverse, for chapter headers `▶ CHAPTER n/6`, `YOUR TX:` lines and the closing `Mine:` line.
  - `internal`/`sequencerAlways`/`feedServer`: magenta `[sequencer]`/`[feed]`.
  - `result`: bold green/red/yellow PASS/FAIL/INCONCLUSIVE.
  - `error`: red, stderr.
  - `style`/`plain`: tables and data (yours rows bold).

  Narration never uses a bare `console.log`. Every non-action explanation starts with `NOTE:`, including banner lines, the matrix legend, reasons and takeaway (`formatMatrix` returns `{table, notes}`, with notes wrapped by `noteBlock` to ≤ 80 columns), and the `tickets:status` clauses. Data, tables, timelines and verdict or action lines stay unprefixed.

  `colorEnabled(isTTY, env)`: a non-empty `NO_COLOR` means off and beats everything. `FORCE_COLOR=0`/`false` means off. Any other non-empty `FORCE_COLOR` means on, even when piped. Otherwise colour follows the stream's TTY. `pga/scripts/demo.sh` applies the same rule. `node --test` injects `FORCE_COLOR=1` when run from a TTY, so `npm test` preloads `shared/test/plain-env.ts` to clear it.

  The hands-off demo waits `chapterDelayMs(isTTY, pause, env, stdinIsTTY)` between chapters: 3 s on a TTY stdout unless a real `--pause` (TTY stdin) waits for Enter; 0 when piped; `DEMO_CHAPTER_DELAY_MS` overrides, and an invalid value exits 2. There is no delay after a failed chapter.
- **Live panel and FF lead (C7):**
  - `FF lead` = the block's visible time on a direct sequencer RPC read (`eth_getBlockByNumber`, one probe per block from its first feed row) − the row's feed `receivedAt`, clamped at 0 (`ffLeadMs`).
  - Round 1 rows lead by about one round more than round 2 rows, because a block is revealed only after its last round.
  - `LiveRounds` groups rows per block with `round R/K` labels and emits `onRow`/`onBlockVisible`. A visible block flushes its pending round at once, without the 300 ms quiet period, and a later block's row completes earlier blocks.
  - On a TTY stdout (`TERM` not `dumb`; `NO_COLOR` drops only colour), demo chapter 4 draws the pure `formatPanel` (open + previous block until block X is known, then only block X (E3); ≤ 80 columns, cut to the terminal height) through `PanelRenderer`. It redraws in place at most every 100 ms, hides the cursor, and restores it on stop, error, SIGINT/SIGTERM (exit 130) and exit. Off a TTY the chapter-4 story is line-based in the same order, and the FF lead is a column of the timing table (E3; before E3 one `FF lead  block N round R/K  tx_index i  +x.xxs` line per row).
  - A `--pause` run honoured on a TTY that starts its own stack uses `--slowmo` (opt out with `DEMO_SLOWMO=0`). Attached, it prints the stack's times and a `NOTE:` hint to restart with `--slowmo`. `feed --local --live` passes the preset's K, so it prints `round R/K` too. On Ctrl-C the demo skips draining the live view and traffic so it exits promptly. Frame errors are counted and reported after the panel stops. A short terminal cuts the previous block first; once block X is known (E3) only block X is shown and the rows are trimmed before the NOTE, the prompt and the sealed line.
- **Simulator clock and pause (E2):** `sim/clock.ts` `SimClock` is the stack's single notion of now: `simNow = (pausedAt ?? wall) − pausedTotal` (frozen while paused), `chainNow = simNow + skipped` (forward-only skips); both never decrease. The sequencer's round schedule, block reveal, `msUntilNext*`/`sim_blockInfo` and block T (`max(floor(chainNow/1000), parent)`) use it, as do `withNow`, the feed auth and the feed's ticket rollover check. Arrival, order (`timestamp_ms`) and client receive times stay wall time. Local RPC: `sim_pause({holder, at:'now'|'afterRound1', leaseMs})` (pauses only between round ticks, so snapshot/re-mine and the `RwGate` are untouched; `afterRound1` holds a block's round 2 open; a `{heartbeat:true}` call by the same holder only extends the lease, another holder is refused with −32000; a 15 s lease auto-resumes), `sim_resume`, `sim_skipTo` (forward only, ≤ one ticket round + 60 s, applied only when no block is open, never blocks: the client polls), `sim_clock` (also in `sim_info`). The proxy keeps accepting txs while paused. Clients compare ticket times with `shared/clock.ts` `chainNowMs()` (wall + offset from `sim_info`, frozen during a hold), never `Date.now()`. PAUSED/RESUMED/CLOCK SKIP log lines are `internal()` (shown by `npm run sim`, hidden in the demo outside its race chapter); `PAUSE LEASE EXPIRED` is always shown. Traffic (`sim/traffic.ts`) pauses with the stack (demo: `pause()/resume()`; standalone: follows `sim_clock`). Consequence: a pause or skip can stretch other clients' waits on a shared stack, so the demo skips only a stack it owns.
- **Fast Feed client (`fast-feed/client/client.ts`)** is reused by later features: optional `Authorization: Bearer $FEED_API_KEY`, binary JSON frames, decodes `raw_tx` with viem, tip = `effective_gas_price − base_fee`, and accepts receipt quantities as number, decimal string or hex. An HTTP rejection at the upgrade (e.g. 401) surfaces as `FeedRejectedError` carrying the status and the server's reason, so commands can print the explanation. `FEED_CODES`/`explainFeedCode` in the client is the single cause/fix map for 401/429/426 and closes 1008/1013/1003/1011, reused by every feed view. `shouldReconnect` and the pure `backoffMs` (1s doubling to 30s, with jitter) drive `feed --reconnect`, which never retries 1003 or 426. `feedApiKey()` in `shared/config.ts` is the single (trimmed) reader of the key, so the string that is hashed and the string that is sent are always identical.

- **Contracts:** `contracts/src/fast-feed/vendor/{Tickets,ITickets}.sol` are byte-for-byte copies of OffchainLabs/feed-ticket-contracts@7cd464fe (Apache-2.0; see the vendor README). Local-only helpers live in `contracts/src/fast-feed/local/` (6-decimals `TestToken`, and a `Proxy.sol` that exists only to emit the `TransparentUpgradeableProxy` artifact). The libraries are git submodules under `lib/` (forge-std v1.16.1, OZ contracts and contracts-upgradeable v5.6.1), and `sim/build.ts` initialises them on a fresh clone. `evm_version = "cancun"` keeps our own contracts deployable on Arbitrum Sepolia.
- **Local deploy:** stack start deploys TEST, the Tickets implementation, `Race` (operator = account 9), then the Tickets proxy as the last deployment (`sim/deploy.ts`, parameters from `shared/config.ts`, admin and beneficiary = Anvil account 9), waits until the first ticket round has started, and publishes the addresses through the `sim_info` RPC method; the local preset resolves them at runtime. Only `sim/deploy.ts` reads `out/` artifacts. The CLI uses the human-readable ABI in `fast-feed/client/abi.ts`.
- **Chain time:** Anvil runs `eth_call`/`eth_estimateGas` at `latest` with the last mined block's timestamp, which goes stale under `--no-mining`. The proxy (`withNow` in `sim/rpc.ts`) therefore adds a `blockOverrides.time = chain now` (the `SimClock` chain clock since E2; equal to wall-clock now while never paused or skipped) to reads at latest/pending, `fast-feed/mock/auth.ts` and `sim/deploy.ts` reuse it, and for `eth_fillTransaction` (which viem's `writeContract` uses) the proxy estimates gas itself with the override before forwarding. Any new direct Anvil read of time-dependent views must do the same.
- **Feed auth (`fast-feed/mock/feed.ts` + `fast-feed/mock/auth.ts`):** at the WebSocket upgrade, the Bearer key is hashed with `apiKeyHash` (`fast-feed/client/key.ts`, the only implementation: keccak256 of the key string's UTF-8 bytes). A key's active tickets in round R are the sum of `numTickets` over its `TicketsPurchased` events with `round == R-1` (`activeTickets`/`accessFor` in `fast-feed/client/access.ts`, which `fast-feed/mock/auth.ts` returns as `{ok, tickets, round, roundEnd}`). A key with 0 active tickets gets HTTP 401, and one with as many open connections as active tickets gets 429. The feed owns per-key connection tracking and a rollover timer: at `roundEnd` it re-checks every connected key and closes its excess connections, newest first, with 1008 `authentication expired` (newest-first is an assumption). The next check time is committed only after a complete pass. A key whose read fails is not closed, and the pass is retried after 1s; an accept can only move the check earlier. A 429 slot is reserved from the 429 check until the connection is registered, the socket closes, or 10s pass, and is released exactly once. A transient Tickets read failure at upgrade answers HTTP 503, which the client retries and explains as a local-only code. It also sends 1003 for client data frames and 1011 on stack stop, and answers 426 for plain HTTP through ws. 1013 is explained but not simulated. `FEED_AUTH=off` restores the open feed, and the banner shows the mode.

### Specification constraints

- Fast Feed messages follow the documented shape `{version, timestamp_ms, pga_round?, transaction:{block_number, tx_index, raw_tx, tx_hash, receipt:{status, gas_used, gas_used_for_l1, cumulative_gas_used, effective_gas_price, base_fee, contract_address, logs}}}`, one JSON object per binary frame, byte fields hex. Locally `timestamp_ms` is the order time of the round (an assumption; the docs say "when the Sequencer created the message"). The mock emitting receipt quantities as JSON numbers and `gas_used_for_l1 = 0` are assumptions (docs do not specify the types).
- Every `--local` value that differs from Arbitrum One is printed by `sim/banner.ts` from `shared/config.ts` (`npm run sim`: the long banner; the demo's chapter 1: the compact table `compactBanner`, ≤ 4 notes); acceleration is never silent.
- Integration tests use the slow preset (B=2000ms, K=2), run on alternate ports, and assert ordering, plus bounds that acceptance criteria state in rounds (e.g. a 1008 within one ticket round), never absolute durations. Every integration suite builds the contracts itself in `before()` (plus a `pretest` script), so `npm test` works on a fresh clone. CLI smoke tests run the real entry points against a temp env file (`ENV_FILE`) and assert that the raw key never appears in their output.
- No mainnet; Sepolia transactions only in the testnet-stage phases. `.env` is git-ignored; the raw feed key and private keys are never printed (public Anvil dev keys excepted in local docs). `pga/video-script.md` (the original `pga.md`, moved unchanged in D1) is not modified.

### Decisions from accepted work

- **A1 (local feed skeleton):** `eth_sendRawTransaction` is intercepted and answered with `keccak256(raw)`, after synchronous "nonce too low" / "insufficient funds" checks like a real node. Because txs wait in our queue rather than in Anvil's pool, the proxy answers `eth_getTransactionCount` for both `pending` and `latest` with max(Anvil nonce, highest queued/in-flight nonce + 1), and patches the nonce in `eth_fillTransaction`, but only when the caller passed no nonce: `cast` asks for `latest` and viem uses `eth_fillTransaction`, so without this, back-to-back sends reuse a nonce. Anvil error `code`/`message`/`data` are forwarded unchanged so revert data stays decodable. The sequencer keeps a hash→raw map, so `raw_tx` is never empty. A block is revealed after its last round's final mine plus `BLOCK_PUBLISH_DELAY_MS` (since B6), so every feed message leads RPC visibility; tests assert ordering only, never the lead's size. Evidence: `fast-feed/test/feed.integration.test.ts`, `shared/test/config.test.ts`.
- **A2 (tickets and feed auth):** `npm run key:new` writes a 64-hex key (no `0x`) to `.env` and prints only its hash, so `cast keccak <key>` gives the same value. `tickets:*` steps are one exported function each in `fast-feed/client/tickets.ts`; `mintLocal` is the only network branch in the ticket steps (entry points branch on mode only to attach to the stack and print). Custom-error reverts are decoded into one-line messages (`formatTicketsError`, with purchase or withdraw context). The CLI's grandfather check applies only when round > 0, as in `Tickets.sol`. `TicketsPurchased` log scans start at the preset's `ticketsFromBlock` (locally the deploy block from `sim_info`). The `tickets:*` commands attach to a running `npm run sim` instead of self-starting, because a stack started by a short-lived command would discard the purchase when the command exits; `feed --local` still self-starts. Ticket rounds are numbered from 0; a ticket bought in round N is active from round N+1. Tests shorten the round with `TICKET_ROUND_SECONDS`, and the banner prints the value in use. Evidence: `fast-feed/test/tickets.integration.test.ts`, `fast-feed/test/tickets.test.ts`, `fast-feed/test/cli.smoke.test.ts`.
- **A3 (connection limits and expiry):** the docs' renewal rule (bought in round N, active in round N+1 only) replaced A2's "active forever after purchase" rule. The error table in `fast-feed/README.md` is the single place each code is explained. Simulator hints in rejection messages are gated on `--local`. Tests buy tickets one at a time, and each local purchase takes about one block. The feed's rules are unit-tested with an injected fake `FeedAuth` (no Anvil), and a test keeps the docs error table and `FEED_CODES` in sync. Evidence: `fast-feed/test/feed-rules.integration.test.ts`, `fast-feed/test/feed-fake-auth.test.ts`, `fast-feed/test/feed-codes.test.ts`, `fast-feed/test/tickets.test.ts`.
- **B1 (tip ordering, delivered before A4 by user decision):** `pga/scripts/demo.sh` mirrors `pga/video-script.md` with `cast`, with one deliberate deviation: after the tick sync it publishes sequentially, lowest tip first, instead of in parallel, so that FIFO and PGA predict opposite orders. It runs only on chainId 31337, or 421614 with `ALLOW_TESTNET=1`, and refuses every other chain. It reads from `READ_RPC` and sends to `RPC`. Exit codes: 0 PGA order, 1 not in tip order or an error, 3 inconclusive, 2 usage; the same-round timing assumes the slow preset. It defaults K1–K3 to Anvil dev accounts 0–2 only on chainId 31337, takes the tip from the receipt (`effectiveGasPrice − block baseFee`; use `cast block N --field baseFeePerGas`), and states honestly when the txs did not share a round. Tests and the demo use the local-only `sim_msUntilNextRound` RPC to send just after a round tick (block-start sync via `sim_msUntilNextBlock` since B6). This makes same-round batching deterministic in the in-process tests, but only best-effort for `demo.sh` across processes, which reports a split honestly. The proxy rejects `eth_sendTransaction`/`eth_sendUnsignedTransaction`, which would bypass the queue: only signed raw txs are accepted, as on the real sequencer endpoint. Locally user txs start at index 0; on Arbitrum index 0 is the ArbOS start-block tx. Evidence: `pga/test/pga-core.test.ts`, `combo/test/pga-order.integration.test.ts`, `pga/test/demo-guard.test.ts`.
- **A4 (live rounds view and traffic):**
  - `fast-feed/client/live.ts` keeps the view in pure functions: row decode (bid from `raw_tx`, effective tip, fee = `gas_used × effective_gas_price`), grouping by (block, pga_round), with block-only when `pga_round` is absent, plus table, timing-line and "yours" formatting. `LiveRounds` completes a round when another round's row arrives or after 300ms of quiet. Its `onTable`/`onTiming` events are the API tests use. Rows whose tip exceeds the row above are annotated `out of tip order (nonce-gated / boosted)`.
  - "Yours" = the `PRIVATE_KEY` address plus `MY_ADDRESSES`, and locally always Anvil account 0. The block-visible probe starts when a round's first row arrives (timed from its `receivedAt`, polling with backoff); the timing line always prints after its table and says "not visible" if the block never appears. Rows whose `raw_tx` cannot be decoded (e.g. ArbOS internal txs) are shown as `(undecodable tx type)` rather than dropped.
  - `sim/traffic.ts` is local-only and attach-only. Each wallet keeps at most one tx in flight, using signed raw type-2 txs with explicit nonces, so traffic never puts a same-sender pair in one round and its rounds stay strictly tip-ordered.
  - The proxy refuses a second tx with the same (sender, nonce) at submit. The check runs immediately before enqueue, with no await between them, so concurrent duplicates of a queued or in-flight nonce cannot both pass. `isKnown(hash)` is re-checked at the same point, so an identical raw tx resubmitted concurrently is idempotent (same hash, no error). This is a model assumption, not documented sequencer behaviour. Rows come from mine's own `ClaimBot` feed connection (`ClaimBotOptions.onFeedMessage`, `TrialOptions.onMineFeed`), so no extra connection or ticket; the visible time is `RaceInput.visibleAt`, valid only when mine's claim block equals `openBlock`, otherwise (or with no rows) one skip `NOTE:` is printed. It runs after `printTrialReport` and reads only the trial, so the verdict and exit code are unchanged. Marking is by address (`<- yours`, `<- rival`). Because the claim usually lands in round 2, round 1 of that block is typically only `open`. Evidence: `combo/test/round2.test.ts`, `combo/test/demo.integration.test.ts` (stacked, piped). The 160-column layout is unit-tested only, not pty-run.
- **D2 (READMEs):** the root `README.md` has six sections: intro, run the full demo (`--pause` first, then hands-off), reading the output, layout with the dependency rule, where next, contributing. `.ts` code prints the anchor `README.md#run-the-full-demo`, so that heading is fixed. Each feature README is self-contained: where the code is, commands in order, and a command reference. `sim/README.md` is the single home of the simulator assumptions and the adaptive ticket-round rule. `pga/README.md` shows a custom tip with `cast send --priority-gas-price` (plus `--gas-price`, because cast's default max fee can be below the tip under traffic); the PGA bot has no `--tip` flag. The `fast-feed/README.md` error table format is pinned by `fast-feed/test/feed-codes.test.ts`.
